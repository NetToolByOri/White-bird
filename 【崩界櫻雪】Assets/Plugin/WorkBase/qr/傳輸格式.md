# 通用 QR 搬運格式

310 分區備份仍產生 SQR1，315 通用 ZIP 產生 SQR2；新版接收器接受兩者。其餘 QR 文字略過，不作為檔案搬運。

一段文字：`SQR2|批次SHA256|總段數|段編號（從1）|封裝總bytes|段CRC32（8位hex）|Base64內容`。
每段原始資料 600 bytes，最後一段可較短。總數必須等於 ceil(size/600)；驗證段大小及 CRC 才能收集。亂序靠編號定位，相同段重複略過。全部收齊後再核對整包 SHA-256。

SQR1 的拼裝資料就是原始備份 ZIP。SQR2 的拼裝資料為：4 bytes 大端序 metadata 長度、該長度 UTF-8 JSON、原 ZIP 原始位元組。JSON 包含 `name` 與 `exportedAt`；metadata 最多 4092 bytes，ZIP 最多 12 MiB。ZIP 不重新打包，因此下載的 ZIP 可以與原始 ZIP 作 byte-for-byte 比較。

其他 HTML 工具可載入`【崩界櫻雪】Assets/Plugin/WorkBase/qr/shion-qr.js`，呼叫 `await ShionQR.open('export-zip', file)`（file 是 name 以 .zip 結尾的 File）或 `await ShionQR.open('import-zip')`。傳输引擎會依需要載入本機 JSZip、SHA、QR、PDF 與辨識插件，不需要四區資料庫。

低階 API 位於 `transfer-codec.js`：`encodeZIP(file)` → parts；`parse(text)` 驗段；`collect(session,part)` 收集；`missing(session)` 缺碼；`assembleZIP(session)` → 原 ZIP bytes、filename；`inspectZIP(data)` 目錄；`extract(contents,name)` → 解壓檔案 bytes 並核對 CRC。session 新建時須保留 part.format、id、total、size 及空 parts 物件。SQR1 舊暫存沒有 format 時視為 SQR1。

PDF 每頁六碼，單冊最多 50 頁。各冊共用同一批次與全域段編號，接收器無需了解分冊或頁次。掃描槍使用 HID 鍵盤模式，可接 Enter／Tab 或已完整的一筆輸入；不需要專用藍牙 API。

完整性校驗沒有密鑰，不提供來源認證或加密。取出 ZIP 內檔案才檢查各檔 CRC，目錄最多 5000 項、單檔解壓最多 64 MiB；超限／特殊 ZIP 可下載原 ZIP 到外部處理。此格式不會自動匯入四區資料；310 還需備份格式及人員關聯檢查。
